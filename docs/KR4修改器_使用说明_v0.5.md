## 一、这是什么

一个注入式 DLL 修改器：把 DLL 注入游戏进程后，在游戏画面上叠加一层 ImGui 工具面板，同时用内联 Hook（inline hook）在游戏关键代码处拦截并改写数值。

- 覆盖层：ImGui 1.90.9 + OpenGL3 后端，挂在 `gdi32!SwapBuffers` 之后绘制，不影响游戏自身渲染状态
- 拦截方式：自研 6 处内联补丁（跳转桩 + 数据槽），通过 MinHook 的 HDE64 反汇编器计算指令长度，在目标 ±2GB 内分配桩内存以支持 rel32 跳转
- 可卸载：END 键或 `unhook` 命令会把 6 处原始指令字节全部写回，桩内存释放，无需重启游戏

## 四、四步上手

1. 从 Steam 启动游戏，等 IronHide 片头结束、进到主菜单。进程名为 `Kingdom Rush Vengeance.exe`。
2. 取 PID，二选一：
   - 任务管理器 → 详细信息 → 找到 `Kingdom Rush Vengeance.exe` → 看 PID 列
   - PowerShell：`Get-Process "Kingdom Rush Vengeance" | Select-Object Id, ProcessName`
3. 注入（在 DLL 所在目录执行）：

   ```
   kr4injector.exe --dll kr4mod_v14.dll --pid 31272
   ```

   成功会打印：`[+] DLL loaded in pid 31272 (remote HMODULE=0x...)`
4. 游戏画面开始刷新后的第一帧，面板自动出现，同时自动安装全部 6 个 Hook（日志里能看到 6 条 pattern hit 与 `%s: 已开启 0x...`）。

## 五、界面说明

面板默认出现在屏幕左上角（40, 40），尺寸 480×860，可拖动标题栏移动，右下角可缩放。

### 1. 顶部状态区

| 显示项 | 含义 |
| --- | --- |
| KR4 修改器 v0.5 (全部功能) | 窗口标题，点右上角 × 只是隐藏面板，不卸载 Hook |
| 注入成功，覆盖层工作正常 | 链路自检通过 |
| 进程 PID | 当前游戏进程号，核对注入目标是否正确 |
| 构建时间 | DLL 编译时间戳，用于确认加载的是哪个版本 |
| 帧率 | 覆盖层自身帧率与单帧耗时，正常 55~60 fps / 17 ms 左右 |
| GL_VERSION | 游戏当前 OpenGL 版本，用于排查渲染问题 |
| INSERT 显示/隐藏面板　END 卸载全部 Hook | 快捷键提示 |
| 中文字体 | 实际加载的字体来源与字号 |
| 扫描候选 | 内存扫描器当前的候选地址数量 |

### 2. 内存扫描区

标题 `内存扫描 (32 位整数)` 或 `内存扫描 (单精度浮点)`，当前扫描数据类型。

- `扫描中... x/y 内存区`：扫描进行中，显示已处理/总内存区数量
- `候选数量: N`：扫描结束后的候选地址数
- 下方最多列出 12 个地址及其当前的 4 字节值；显示 `<已失效>` 表示该地址已不可读（堆变化后正常现象）
- 状态行：中文状态说明，如「正在扫描…」「已过滤…剩余 N 个候选」「扫描完成: N 个命中，耗时 N 毫秒」「已清空」

扫描器没有按钮，全部通过命令通道驱动，见第八节。

### 3. 金币区

- 标题 `金币 Hook（整数写入拦截）`
- 状态行显示：`未安装` / `在游戏模块中未找到特征码` / `已挂钩 0x...（桩代码 0x...）` / `金币锁定已开启（数值 999999）` / `金币锁定已关闭`
- `开启金币锁定` / `关闭金币锁定`：切换锁定开关
- 数值输入框（默认 999999，步进 100000 / 1000000）：锁定后的目标金币数；输入即生效，不必关开
- Hook 未安装时该处显示 `安装金币 Hook` 按钮

### 4. 功能补丁区

从上到下 5 行状态，分别是：

```
生命锁定: 已开启 0x...（或 未找到特征码 / 已卸载）
友军伤害: ...
英雄经验: ...
英雄技能: ...
升级点:   ...
```

按钮行：`一键安装全部` / `全部开启` / `全部关闭`。三者区别：安装只打补丁不改变开关状态，开启/关闭是切开关。

### 5. 复选框与倍率输入

| 控件 | 说明 | 默认值 |
| --- | --- | --- |
| 生命锁定 | 我方单位血量写入固定值 | 9999 |
| 友军无敌 | 我方/友军受到的伤害归零（与一击必杀配合） | 关 |
| 一击必杀 | 敌方单位血量直接清零 | 关 |
| 伤害倍率 | 我方输出伤害乘以倍数，1 为原样 | 1 |
| 英雄经验锁定 | 英雄经验总量锁定不增长 | 关 |
| 经验倍率 | 获得经验乘以倍数 | 1 |
| 技能点免消耗 | 技能点不足也可升级 | 关 |
| 升级点锁定 | 升级点数量固定为设定值 | 99 |

## 六、功能与实测情况

| 功能 | 生效机制 | 实测结论 |
| --- | --- | --- |
| 金币锁定 | 在金币写入函数返回前，把待写入值替换为锁定值 | 已实测：金币 999999，关卡内消耗 80 金币时写入值被替换为 999999，HUD 显示不变且不扣减 |
| 生命锁定 | 拦截单位血量写入，替换为 9999 | Hook 已安装并命中（calls 递增），画面正常 |
| 友军无敌 / 一击必杀 | 拦截单位伤害结算，区分我方与敌方 | Hook 已安装并命中 |
| 英雄经验锁定 / 经验倍率 | 拦截英雄经验累加 | Hook 已安装并命中 |
| 技能点免消耗 | 拦截技能点判定跳转 | Hook 已安装并命中 |
| 升级点锁定 | 拦截升级点写入 | Hook 已安装并命中 |

说明：数值类功能都是「运行时改写」，游戏重启后回到原始数值；金币锁定只在写操作发生时改写，因此不会把存档数值改成异常值。

## 八、内存扫描器（手动定位数值）

用于在不知道地址时自行定位某个数值（金币、生命、钻石等）。两个扫描函数分别对应整数与浮点，游戏里大部分数值是单精度浮点，定位数值优先用 `scanf` / `filterf`。

典型流程（以金币为例）：

1. 记下当前金币，假设 170 → 写命令 `scanf 170`
2. 回到游戏花掉一部分，假设剩 90 → 写命令 `filterf 90`
3. 重复第 2 步直到候选只剩 1~3 个（面板上能看到地址和当前值）
4. 写命令 `writef 5000` 把候选地址全部改成 5000
5. 不需要时 `clear` 清空候选

要点：

- 扫描是全进程内存遍历，每步耗时 1~3 秒，期间游戏会略微掉帧，属正常
- 过滤时数值类型必须与首次扫描一致（float 对应 scanf/filterf/writef）
- 候选地址在场景切换后可能失效，重新扫描即可

## 九、命令通道速查

把命令写入 `%TEMP%\kr4mod_cmd.txt`，修改器每帧轮询一次，检测到文件内容变化就执行。

PowerShell 写法（`-NoNewline` 可省，但建议加，避免多余换行）：

```powershell
"mon" | Out-File -FilePath "$env:TEMP\kr4mod_cmd.txt" -Encoding ASCII -NoNewline
```

两条重要规则：

1. 只有文件内容变化才执行。想重复执行同一条命令，先写别的命令再写回来，或在命令后加空格。
2. 注入后的第一次轮询会丢弃文件里的残留内容（日志记 `cmd channel primed`），不会误触发上次会话的命令。

## 十、日志怎么看

`%TEMP%\kr4mod.log`，逐行追加，带毫秒时间戳。关键行：

| 日志内容 | 含义 |
| --- | --- |
| `font loaded: C:\Windows\Fonts\simhei.ttf` | 中文字体加载成功（若为 `falling back to default` 则会出现方块，需装字体） |
| `hooked gdi32!SwapBuffers @ 0x...` | 渲染挂点成功 |
| `hk 生命锁定: 已开启 0x...` | 某 Hook 安装成功并给出目标地址 |
| `hk 英雄技能: 未找到特征码` | 该 Hook 定位失败，通常是游戏版本不匹配 |
| `stats: frames=N glErrors=0 fps=58.9 vtx=... idx=...` | 每 3 秒一次渲染统计，glErrors 应为 0 |
| `money: calls=1 getter=... wouldWrite=... applied=... locked=1` | 金币 Hook 的拦截明细 |
| `cmd channel primed (stale command ignored)` | 注入后已丢弃残留命令 |
| `unhooked (overlay disabled)` | 卸载完成，6 处原始指令已还原 |

## 十一、卸载与换版本

标准流程（推荐）：

```
1) 写 unhook 命令 → 等日志出现 "unhooked (overlay disabled)"
2) 注入新的 DLL（新版文件名不要复用旧名，避免文件占用）
```

- 直接按 END 键效果相同
- 若游戏直接退出，6 处补丁随进程销毁自动消失，不会残留到下次运行
- 换版本时不要跳过第 1 步：旧 DLL 的 Hook 还在，会把新版跳转覆盖，导致地址混乱

## 十二、常见问题

**面板不出现**
看日志有没有 `hooked gdi32!SwapBuffers`。有则检查是否按了 INSERT 隐藏；没有说明 DLL 没跑起来，确认注入器返回值与会话权限。独占全屏下覆盖层可能不显示，建议窗口化或无边窗口运行。

**面板里中文变方块**
系统缺中文字体，装「黑体」或「微软雅黑」即可（`simhei.ttf` / `msyh.ttc`）。日志会显示 `font: falling back to default`。

**弹出 ImGui 断言框、画面卡死**
imGui 版本混用导致（`IMGUI_CHECKVERSION()` 失败），必须统一用 imgui-1.90.9 编译，并加 `-DNDEBUG`。当前版本已规避。

**重新链接 DLL 时报 Permission denied**
旧 DLL 还被游戏进程占用。先把旧版 unhook，或直接改用新文件名输出。

**鼠标点不到游戏**
面板显示时会接管鼠标，按 INSERT 隐藏面板即可。

**想彻底关掉覆盖层但保留 Hook**
在 `%TEMP%` 放一个名为 `kr4mod_render.off` 的空文件，覆盖层停止绘制，Hook 继续生效。

**帧率从 60 掉到 55 左右**
覆盖层每帧绘制约 2 ms，属正常开销。

## 十三、技术附录

### 1. 六个 Hook 目标（RVA，相对游戏主模块基址）

| Hook | RVA | 原始指令字节 |
| --- | --- | --- |
| 金币 | `0x1CD140` | `8D 14 07 48 8B CE FF 93` |
| 生命 | `0x1CD296` | `8D 14 07 48 8B CE FF 93` |
| 单位伤害 | `0x385A90` | `44 8B F0 29 83 C4 0C 00` |
| 英雄经验 | `0x37DBC0` | `F3 0F 58 C8 F3 0F 2C C1` |
| 英雄技能 | `0x3D8470` | `3B 87 E0 06 00 00 7C A4` |
| 升级点 | `0x74DE0` | `8B 4B 44 2B C8 8B C1 48` |

技能点的特征码为带通配的 AOB：`3B 87 <off> 7C 00 8B 87 <off> 39`，掩码 `xx????x?xx????x`。

### 2. 桩内存布局

| 区段 | 说明 |
| --- | --- |
| `stub + 0x00` | 各 Hook 数据槽起点：flag `+0x00`、amt `+0x04`、calls `+0x08` |
| `stub + 0x10 / +0x14 / +0x18` | 最近一次 lastEdx / lastEax / lastEdi，用于核对拦截到的参数 |
| `stub + 0x40` | 逻辑代码区（HK_LOGIC，0x40 字节） |
| `stub + 0xC0 ~ +0xE0` | 金币专用数据槽 |
| `stub + 0xE8` | 金币倍率 `g_moneyMul` |
| `stub + 0x180` | 数据区（HK_DATA，0x180 字节） |

写 6 字节跳转时先写尾 5 字节、最后写首字节 `E9`，避免执行到半成品指令。

### 3. 编译命令（MinGW-w64 g++，静态链接）

```
g++ -c -O2 -DNDEBUG -std=c++17 -finput-charset=UTF-8 -fexec-charset=UTF-8 ^
    -Isrc -Ithird_party/imgui-1.90.9 -Ithird_party/imgui-1.90.9/backends ^
    -Ithird_party/minhook-master/include src/overlay.cpp -o overlay.o

g++ -shared -o kr4mod_v14.dll overlay.o imgui.o imgui_draw.o imgui_tables.o ^
    imgui_widgets.o imgui_impl_opengl3.o impl_win32.o ^
    mh_buffer.o mh_hde64.o mh_hook.o mh_trampoline.o ^
    -static -static-libgcc -static-libstdc++ ^
    -lopengl32 -lgdi32 -luser32 -limm32 -ldwmapi -lshcore -lole32
```

源码必须存为 UTF-8（带或不带 BOM 均可），编译加 `-finput-charset=UTF-8 -fexec-charset=UTF-8` 保证中文字面量以 UTF-8 进入二进制。

### 4. 渲染要点

- 使用 `imgui_impl_opengl3`（VBO + `#version 150` shader）。早期用 opengl2 后端配合 `glBegin/glEnd` 在游戏的 core 上下文里会被忽略，面板完全不显示
- 绘制前后用 `glPushAttrib(GL_ALL_ATTRIB_BITS)` / `glPushClientAttrib` / `glPushMatrix` 快照游戏状态，否则会把整个场景染成洋红
- 覆盖层挂 `SwapBuffers`，首帧初始化 ImGui（需 GL 上下文就绪）

### 5. 已知限制

- 特征码只对应当前 Steam 构建（App ID 1367550）。游戏更新后 Hook 点会失效，日志出现 `未找到特征码`，需重新定位
- 仅单机使用，联机/云存档同步场景不要开
- 修改只作用于内存，不写存档文件
